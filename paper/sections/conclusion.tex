\section{Conclusion}
\label{sec:conclusion}
We built a hybrid RAG pipeline that runs entirely on a laptop and used it to
ask whether the balance between dense and sparse retrieval should be set per
query. Fusion helps when the two retrievers are comparably strong and fail on
different queries; on identifier-heavy RFC text BM25 is hard to beat, and a
weight tuned on other collections hurts. Our LLM-free QAF model is cheap and
easy to inspect, but it does not reliably beat a fixed weight: its features
explain little of the oracle weight, and it behaves mostly like a shrunk
constant. The oracle headroom is real, so the problem is worth more work.
