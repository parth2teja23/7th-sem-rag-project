\section{Experimental Setup}
\label{sec:setup}

\subsection{Datasets}
\label{sec:data}
Table~\ref{tab:data} lists the four test collections: scientific claims,
informal financial questions, multi-hop questions with short answers, and a
corpus full of protocol identifiers.

\textit{SciFact}~\cite{wadden2020scifact} and \textit{FiQA}~\cite{maia2018fiqa}
come from BEIR~\cite{thakur2021beir}. SciFact has no dev split, so we hold out
a seeded 20\% of its training queries. To keep encoding time manageable we
index 20{,}000 of FiQA's 57{,}638 posts: every post judged relevant for a dev
or test query (2{,}944) plus a seeded random sample of the rest. FiQA scores
are therefore not comparable with full-corpus BEIR numbers.
\textit{HotpotQA}~\cite{yang2018hotpotqa}: 500 seeded questions from the
distractor validation set; the corpus is the union of their paragraphs,
deduplicated by title, and the supporting paragraphs are relevant. It also
supplies gold answers for the generation experiments.

\textit{RFC corpus.} This collection targets questions about exact
identifiers. It holds 20 IETF
RFCs, from IP and TCP (RFC~791, 793) through DNS, HTTP/1.1, URI syntax, IPv6,
SMTP, WebSocket, OAuth~2.0, JWT, JSON and TLS~1.3 to QUIC and the 2022 HTTP
documents (RFC~9110, 9112, 9113). After removing page headers and footers, the
chunker of Section~\ref{sec:chunking} yields 2{,}973 chunks of about 180 words
on average. Qwen2.5-7B drafted one question per sampled chunk that contained at
least two identifier-like tokens, with an answer of at most eight words copied
verbatim from the chunk. Automatic filters rejected malformed or truncated
answers, questions pointing at the text itself (``this document''), duplicate
questions or answers, and answers occurring more than once in their chunk or
more than three times in the parent RFC; we also capped each RFC at 12
questions and each section at two. The 180 drafts that passed went through an
AI-assisted screening pass, after which all three authors checked every row
against the RFC text and kept 101. For example, one question asks for the
length of the interface identifier in IPv6 unicast addresses (``64 bits'').
A chunk is relevant if its character span overlaps the answer span in the
source, which covers answers that fall inside an overlap region.

\subsection{Configurations}
For every collection and encoder we run \textbf{BM25} and \textbf{Dense}
alone; \textbf{Hybrid-fixed}, i.e.\ Eq.~\eqref{eq:rrf} with one weight
$\alpha^{*}$; \textbf{QAF}; both hybrids followed by reranking
(\textbf{+RR}); and an \textbf{Oracle} that uses each query's plateau-centre
oracle $\alpha$ (Section~\ref{sec:qaf}) computed on the test labels. Because the
centre of a plateau can fall between grid points, this is not a strict upper
bound; we use it as a reference for how much headroom per-query weighting has,
and report QAF's gap to it. $\alpha^{*}$ is the grid
value with the best mean nDCG@10 over the pooled SciFact and FiQA dev queries
(ties go to the value nearest 0.5) and is applied unchanged to all test sets
($\alpha^{*}=\AlphaStarBge$ for BGE, $\AlphaStarGemma$ for EmbeddingGemma~2).
We also sweep the fixed $\alpha$ over the grid on every test set, and test
transfer by fitting QAF on one dev set and evaluating on the other dataset
(leave-one-dataset-out).
% NOTE(results): revise if not run (ablation).
The ablation removes one component at a time from the
full system: structural chunking (RFC only), query expansion, QAF (replaced by
$\alpha^{*}$) and the reranker.
% NOTE(results): revise if not run (Matryoshka).
For EmbeddingGemma~2 we repeat Dense and QAF+RR at 512, 256 and 128
dimensions; at each size QAF is retrained on the same pooled dev queries and
$\alpha^{*}$ is re-selected.
% NOTE(results): revise if not run (generation).
Generation is evaluated on HotpotQA and
RFC for BM25, Dense (stronger encoder), Hybrid-fixed+RR and QAF+RR.

\subsection{Metrics}
Retrieval is scored with Recall@$k$ ($k\in\{5,10,20\}$), MRR@10 and
\begin{equation}
  \mathrm{nDCG@}k=\frac{1}{\mathrm{IDCG@}k}\sum_{i=1}^{k}\frac{2^{\mathit{rel}_i}-1}{\log_2(i+1)},
  \label{eq:ndcg}
\end{equation}
where $\mathit{rel}_i$ is the graded relevance at rank $i$ and IDCG@$k$ is the
same sum for the ideal ordering~\cite{jarvelin2002ndcg}. A query with no
returned passages scores zero rather than being dropped. Answers are scored by
SQuAD-style~\cite{rajpurkar2016squad} exact match (EM) and token F1 after
lowercasing and removing punctuation and articles, and we record whether any
cited passage is relevant.
% NOTE(results): revise if not run (RAGAS).
Faithfulness to the retrieved context is judged with
RAGAS~\cite{es2024ragas} on \RagasN{} answers, with the local Qwen2.5-7B as
judge. For the headline comparisons (QAF+RR against Hybrid-fixed+RR and
against Dense) we test whether the per-query nDCG@10 gain exceeds zero with a
one-sided paired bootstrap (10{,}000 resamples, seed 42) and a one-sided paired
$t$-test.

\subsection{Implementation and hardware}
Everything runs on one Apple M5 MacBook with 32\,GB of memory, with encoders
and reranker on PyTorch's MPS backend, the LLM in Ollama, and no paid API. The
code uses Python~3.12, sentence-transformers, FAISS, bm25s and scikit-learn.
Encoding dominates offline cost: EmbeddingGemma~2 encodes about
\GemmaDocsPerSec{} passages per second and BGE-small \BGEDocsPerSec{}, so
encoding the FiQA subset with the larger model takes about
\FiQAEncodeMinGemma{} minutes. Each query's two top-100 lists are computed
once and cached, all fusion variants are derived from them, and cross-encoder
scores are cached per query--passage pair; a test confirms that this path gives
the same rankings as the end-to-end pipeline. Latency is recorded per stage as
mean and 95th percentile. All sampling uses seed 42.
